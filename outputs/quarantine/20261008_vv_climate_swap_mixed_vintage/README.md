## 1. The bug
During the 10-08 vv rerun (`run_vv_zenodo_rerun_20261008.sh downstream`), the first downstream pass failed. A
partial retry at 18:22 (`outputs/log_vvz_downstream_retry.txt`) ran `plot_vv_climate_swap.py` without re-running
`vv_model_comparison.py`. The swap therefore paired:

- the **pre-rerun** comparison table (still at its canonical path, unconditioned, harmonized-tail emissions) for
  the FaIR-driver points of Ladrillo and BRICK 2.0;
- the **post-rerun** MAGICC-climate arms (published Zenodo emissions).

[ARM-MATCH] only compared draw COUNTS, and the stale table still said 2,000 draws, so it passed.
- The final pass at 18:25 rebuilt the comparison table with 1,998 draws. [ARM-MATCH] then refused, so nothing
  overwrote the retry's files.
- The 10-08k CHANGELOG, the handoff and the 20261008_vv_zenodo_conditioning_arms README all say the swap was "NOT
  regenerated". It had been, wrongly, and was committed in e567ea7.

**Measured.**
- The FaIR-side medians in these files equal the quarantined pre-rerun comparison table exactly (max |d| = 0).
- They differ from the live table by up to 10.4 cm (Ladrillo) and 13.7 cm (BRICK 2.0).
- Worst cell: Ladrillo vvML 2300. The TE climate term reads −1.4 cm; the correct value is −8.6.

These are the same paths outside `quarantine/`, regenerated by `python/plot_vv_climate_swap.py --tag=L27 --year=all`
after the fix. Three gates were added, each mutation-tested:
- **[SOURCE-MATCH]:** the comparison table's FaIR cells must equal the driver's cells files. A stale table fails it.
- **[RECOMPUTE-IDENTITY]:** the MAGICC cells recomputed from the per-draw file must equal the driver's cells.
- **[ARM-MATCH] keyed by DRAW ID:** Ladrillo's MAGICC point is computed on the COMMON draw set, i.e. minus the FaIR
  arm's REJECTED draws 187 and 610 (Marcus 10-08). That moves it by ≤ 0.16 cm.
